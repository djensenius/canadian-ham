## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the task-12.2 re-review found two small TS/Swift differences in text handling. (1) TS treats U+FEFF (byte-order mark) as whitespace but not U+0085 (NEL); Swift does the reverse, so pasted text can be skipped in one language and reported invalid in the other. (2) A decomposed É in the learner's typed copy scores as a correct E plus an inserted mark, while a precomposed É scores as one wrong character; pass/fail is the same but the error breakdown differs.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 TS and Swift use one explicit shared whitespace list, with fixtures for U+FEFF and U+0085
- [x] #2 The received copy is NFC-normalised before scoring in both languages, with a fixture showing decomposed and precomposed É score identically
- [x] #3 pnpm test and swift test in packages/morse-swift pass
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Align TS and Swift Morse text handling on one explicit whitespace list, including U+FEFF and U+0085.
2. NFC-normalize received copy before scoring in both engines and lock the behavior with shared fixtures.
3. Verify parity with package tests, swift test, pnpm test, web build/audit, and full Apple platform runs because morse-swift changed.
<!-- SECTION:PLAN:END -->
